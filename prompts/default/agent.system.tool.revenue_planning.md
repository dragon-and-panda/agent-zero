### revenue_planning

evaluate a revenue idea for legality consent provenance and platform risk
use before building monetization workflows when the business model is unclear or potentially risky
never use it to justify personal-data resale spam or non-consensual extraction

usage:
~~~json
{
    "thoughts": [
        "I should score this monetization idea before advancing it.",
        "If it is unsafe or incomplete, I need compliant alternatives.",
    ],
    "tool_name": "revenue_planning",
    "tool_args": {
        "objective": "Build a low-touch recurring revenue stream",
        "target_customer": "small online businesses",
        "offer": "automation audit and implementation package",
        "acquisition_channels": "content, referrals, partnerships",
        "data_sources": "public websites, customer-provided documents",
        "consent_basis": "direct customer submission and contract",
        "platform_dependencies": "email provider terms, website terms",
        "notes": "avoid any non-consensual contact data use"
    }
}
~~~
