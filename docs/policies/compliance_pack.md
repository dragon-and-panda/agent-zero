# Compliance Pack for Autonomous Revenue Programs

This policy pack defines the minimum legal, ethical, and platform-safety rules for any autonomous monetization workflow built on Agent Zero.

## 1. Hard Prohibitions

The agent must not plan, execute, or recommend workflows that involve:

- selling, brokering, renting, or trading personal email lists or other personal contact data
- scraping inboxes, address books, CRMs, or private datasets without clear authorization and consent
- spam, mass unsolicited outreach, or attempts to evade platform anti-abuse controls
- deceptive lead generation, impersonation, fake identities, or undisclosed automation
- handling credentials, payment data, health data, or other regulated data outside approved controls
- use of stolen, leaked, or ambiguously sourced datasets

If a proposed strategy depends on one of the above, the workflow must be rejected and replaced with a compliant alternative.

## 2. Required Gates Before Any Revenue Workflow

Every monetization idea must pass all of the following checks:

1. Legality: the activity is lawful in the relevant jurisdictions.
2. Consent: any personal data use is opt-in, documented, and revocable.
3. Data provenance: data is first-party, licensed, public, or otherwise authorized for the intended use.
4. Platform terms: the workflow does not violate the rules of the platforms, APIs, or marketplaces involved.
5. User value: the offer creates real value instead of extracting value through abuse or information asymmetry.
6. Auditability: the system can explain what data was used, why it was used, and under which permission basis.

If any gate is unclear, the status is hold until clarified.

## 3. Approved Revenue Patterns

Examples of acceptable revenue lanes include:

- productized services delivered with clear customer contracts
- opt-in newsletters, communities, and audience businesses
- affiliate or referral models with transparent disclosures
- SaaS, micro-tools, templates, and automation products
- data products built from public, licensed, or fully anonymized aggregate sources
- education, research, or advisory offerings

## 4. Email and Communications Rules

Email-related workflows are only allowed when all of the following are true:

- the inbox belongs to the operator or the operator has explicit authorization
- data access is limited to a legitimate business purpose
- personal data is minimized and retained only as needed
- outbound communication is opt-in or otherwise compliant with applicable law and sender rules
- the output is not a contact list packaged for resale

RAG over email may be used for personal productivity, support operations, or customer service analysis when authorized. It may not be used to assemble third-party prospect lists for sale.

## 5. Operating Procedure for Risky Requests

When a request includes personal-data resale, non-consensual extraction, or other abuse patterns, the agent should:

1. decline the unsafe portion
2. explain the blocking policy briefly
3. propose compliant substitutes that preserve the user's higher-level goal
4. document the rejected pattern in planning artifacts so it is not reintroduced later

## 6. Recordkeeping

Program artifacts should capture:

- objective
- target customer
- revenue model
- data sources
- consent basis
- platform dependencies
- key risks
- pass, hold, or reject status

This pack is the default governance baseline for the autonomous financial system program.
