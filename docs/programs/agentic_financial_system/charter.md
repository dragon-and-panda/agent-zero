# Agentic Financial System Charter

## Mission

Build a self-sustaining, low-touch financial system that increases revenue through lawful, ethical, and automatable online ventures.

## Non-Negotiable Constraints

- no contact-list brokerage
- no private-data harvesting
- no non-consensual inbox mining
- no spam-based growth
- no revenue lane with unclear legality, provenance, or terms-of-service fit

See `docs/policies/compliance_pack.md` for the governing policy set.

## Operating Thesis

Durable autonomous revenue should come from repeatable value creation, not from extracting value out of third-party personal data.

## Core Venture Lanes

### Lane 1: Inbox-to-CRM Automation

Use RAG only on user-owned or explicitly authorized business communications to:

- summarize inquiries
- extract structured opportunities
- update CRM records
- route follow-up work

Revenue model:

- internal efficiency gains
- productized service
- SaaS workflow

### Lane 2: Autonomous Listing and Marketplace Operations

Use the existing listing-service concepts in this repo to:

- create listings
- improve copy and visuals
- monitor inbound demand
- automate follow-up and qualification

Revenue model:

- listing management fees
- performance-based retainers
- marketplace tooling

### Lane 3: Public-Data Research Products

Create recurring reports, dashboards, or niche intelligence products from:

- public records
- public web content with compliant access
- licensed datasets
- internally generated usage data

Revenue model:

- subscriptions
- one-off reports
- premium alerts

### Lane 4: Opt-In Audience and Distribution Assets

Build permission-based distribution:

- newsletter
- waitlist
- community
- content funnel

Revenue model:

- sponsorships
- affiliates
- product launches
- owned audience conversion

### Lane 5: Productized Agentic Services

Package repeatable agent workflows such as:

- lead qualification on first-party forms
- support triage
- research assistance
- back-office automation

Revenue model:

- monthly retainers
- setup fees
- usage-based pricing

## Lane Prioritization Rules

Prefer opportunities that score well on:

- legality
- consent quality
- data quality
- speed to first revenue
- gross margin
- repeatability
- automation leverage
- defensibility

Use `instruments/strategy/score.sh` before committing major effort.

## Program Cadence

1. capture new ideas in `docs/strategy/incoming.md`
2. score each idea
3. reject non-compliant lanes immediately
4. advance one primary lane and one hedge lane at a time
5. log each meaningful decision in `journal.md`
6. move reusable learnings into the broader docs and prompt layers

## Initial Recommendation

Start with Inbox-to-CRM Automation as the primary lane because it uses first-party data and can create immediate operational value without requiring external distribution at the outset.
