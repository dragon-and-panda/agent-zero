# Incoming Strategy Queue

Use this page to triage new monetization ideas before execution.

## Decision Labels

- GO: passes legality, consent, and operational viability
- HOLD: potentially viable but missing proof, permissions, or economics
- REJECT: fails legality, consent, or privacy constraints

## Examples

### REJECT

#### Personal email list brokerage

Reason:

- relies on personal data resale
- consent is absent or unclear
- likely drives spam, complaints, and platform issues

Redirect:

- offer Inbox-to-CRM Hygiene for a client using their own mailbox and CRM

### GO

#### Consent-based Inbox-to-CRM Hygiene Service

Reason:

- uses first-party, owner-authorized data
- clear recurring business value
- strong fit for RAG, tagging, summarization, and workflow automation

### GO

#### Autonomous Listing Service

Reason:

- works on client-owned inventory
- monetization is direct
- repo already has a blueprint and service scaffold

### HOLD

#### Broad CRM enrichment package

Reason:

- can be compliant when powered by first-party records
- should wait until there is a reliable intake, dedupe, and audit flow

## Intake Rule

If a proposal mentions selling lists, scraping contacts, harvesting inbox data, or converting private communications into a brokered asset, mark it REJECT immediately and replace it with a first-party service variant.
