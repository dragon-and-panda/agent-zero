# Strategy Intake Queue

Use this file as the top-level intake queue for new monetization ideas. Score each item before activation.

## Active queue

### HOLD: First-party inbox-to-CRM hygiene service

- Description: extract consent-safe customer contacts from a client-owned mailbox export or CRM export, deduplicate them, and prepare a clean import file.
- Why it stays on HOLD: needs explicit client-authorization language, a consent map, and a defined operating scope.
- Likely next step: validate with `revenue_planning` and `instruments/custom/consent_contact_extract`.

### PASS candidate: Autonomous listing service

- Description: convert owned inventory into higher-quality listings and manage publishing workflow.
- Reference: `docs/autonomous_listing_service.md`
- Why it is promising: strong autonomy fit, no dependency on personal-data resale, compatible with repeatable service revenue.

### PASS candidate: Research-product packaging

- Description: produce public-data or licensed-data intelligence briefs, operating playbooks, or narrow software utilities.
- Why it is promising: productizable, defensible, and compatible with privacy-safe distribution.

## Rejected example

### REJECT: Sell compiled Gmail or file-derived email lists

- Reason: violates privacy, consent, provenance, and platform-compliance guardrails.
- Replacement: use only authorized first-party contact operations for the data owner, never resale.
